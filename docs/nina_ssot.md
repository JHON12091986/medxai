## What This File Is

`docs/nina_ssot.md` is the **human-readable truth layer** of NINA's Single Source of Truth system.
The machine-readable counterpart is `data/nina_ssot.json`.

Both are generated by `tools/nina_ssot.py` in a single invocation that runs 4 phases:

```
1. DISCOVER
   ├── walk all .py files → AST → constants, string literals, function args
   ├── walk .env + .env.local → all key=value pairs
   ├── call dependency_mapper → import graph
   ├── call symbol_mapper → function/class index
   └── walk .sh scripts → env var references

2. ANALYSE
   ├── group env keys by identical value → alias clusters
   ├── elect canonical name (most imported in .py files)
   ├── detect aliases (same value, different name)
   ├── detect orphans (defined in .env, never imported)
   ├── detect hardcoded strings (should be constants)
   ├── detect broken chains (env key → config → function → broken)
   └── detect file drift (file exists, not in graph)

3. WRITE
   ├── data/nina_ssot.json   ← machine truth
   └── docs/nina_ssot.md     ← human report (this file)

4. ENFORCE
   ├── alias in .env → VIOLATION
   ├── hardcoded key string in .py → VIOLATION
   ├── orphan env var → VIOLATION
   ├── broken import chain → VIOLATION
   └── exit 1 if any violations, exit 0 if clean
```

## Integration

`nina_sync.sh` calls `tools/nina_ssot.py` on every sync cycle:
- **exit 0** → sync continues normally
- **exit 1** → sync **BLOCKED**, violations printed to stdout

This means every `ngit` push followed by `sync` will automatically enforce SSOT compliance.
