Install on your machine
# 1 · copy the .sh file to ~/nina/ cp nina-guardian.sh ~/nina/nina-guardian.sh chmod +x ~/nina/nina-guardian.sh # 2 · auto-activate venv when you cd into ~/nina echo 'function cd() { builtin cd "$@" && [ -f venv/bin/activate ] && source venv/bin/activate; }' >> ~/.bashrc source ~/.bashrc # 3 · one-shot check + restart cd ~/nina && bash nina-guardian.sh # 4 · shortcut alias (optional) echo "alias nina='cd ~/nina && bash nina-guardian.sh'" >> ~/.bashrc
Prevention rules
Rule 1
Always run Guardian before deploy
Never restart nina.service without running bash nina-guardian.sh first. Catches syntax errors and name errors before production.
Rule 2
Never edit outside venv
cd ~/nina auto-activates the venv. Never run healthcheck.py with system Python.
Rule 3
main.py pattern is sacred
nina.start() + await asyncio.Event().wait(). Wrong method = crash. No keep-alive = restart loop.
Rule 4
Check logs 5s after restart
journalctl -u nina -n 20 --no-pager every deploy. Don't assume NINA is alive without checking.
