🛡️ Sentinel: [CRITICAL] Fix command injection vulnerability by hardcoding shell=False

🚨 Severity: CRITICAL
💡 Vulnerability: `subprocess.run` was called with `shell=use_shell` where `use_shell` could be `True`, allowing potential command injection in the base execution primitives within `tools/agynina.py` and `guardian_engine.py`.
🎯 Impact: Untrusted input or maliciously crafted strings passed to these execution utilities could be evaluated by the system shell, leading to arbitrary command execution.
🔧 Fix: Removed the `use_shell` parameter and hardcoded `shell=False` in `run_cmd` for both files, strictly enforcing argument tokenization via `shlex.split`. Additionally, refactored a brittle `&&` shell chaining execution in `tools/agynina.py` to use discrete `run_cmd` calls instead, preserving functionality while allowing `shell=False`.
✅ Verification: Ran `bandit` to ensure no `shell=True` warnings remained and passed the full `pytest` suite locally.
