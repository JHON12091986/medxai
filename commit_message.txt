⚡ Bolt: Pre-compile regex patterns in UpgradePipeline

💡 What:
Pre-compiled the regular expression definitions within `tools/upgradepipeline.py`'s `DANGEROUS_PATTERNS` at the module level. Changed `re.search` calls in the hot path (`_scan` method) to use the pre-compiled `pattern.search`.

🎯 Why:
The `_scan` method is called repeatedly to validate dynamically submitted code snippets against numerous regex patterns. Re-compiling these regular expressions dynamically using `re.search()` inside the loop introduces redundant compilation overhead during hot-path operations.

📊 Impact:
Removes redundant C-level state machine compilation overhead for large arrays of regex patterns, marginally improving scanning throughput in the upgrade pipeline.

🔬 Measurement:
Running benchmarking simulations on 10,000 iterations over a long code payload verifies that the compiled pattern matching behaves correctly and completes faster. All downstream test suites (e.g. `test_tools_smoke.py`) were successfully refactored to validate against `p.pattern` and pass smoothly.
